# Decisions

Status is `proposed` or `accepted`. Accepted entries are never edited, only superseded by a new entry.

## D-001 Platform and stack (accepted)
Native Android only, Kotlin + Jetpack Compose, phone-first with tablet-tolerant layouts. Single module `app`.

## D-002 Business model and privacy (accepted)
Free. No ads, no purchases, no analytics, no third-party SDKs that phone home. The `INTERNET` permission is not declared.

## D-003 Offline-first storage (accepted)
All audio and art bundled. Progress and settings stored locally with DataStore. No accounts, no backend.

## D-004 Collaboration (accepted)
Repository on GitHub. Claude Code and Codex share one branch, one writer at a time, everything resumable from files.

## D-005 Child rules (accepted)
No failure states, no wrong-answer sounds, no timers or streaks aimed at the child, touch targets at least 64dp, every word has audio, parent-only areas behind a parental gate.

## D-006 Language (proposed)
English UI and audio. The word schema has a `translations` map keyed by locale (for example `"ur": "..."`) so a first-language gloss can be added later. The parent corner is in English.

## D-007 Project location and relation to TinyTalk (proposed)
This app lives in its own repository and folder, `C:\Users\hp\AndroidStudioProjects\toddler-english-app`.
The folder `MIM` next to it holds a different app (TinyTalk, ages 2 to 6, adventure game) with its own
handover rules and owner decisions. It is left untouched. Nothing is copied from it except the Gradle wrapper
and the dependency versions already proven to build on this machine.

## D-008 SDK levels (proposed)
`minSdk = 24`, `compileSdk = 36`, `targetSdk = 36`. Google Play requires new apps and updates to target
Android 16 (API 36) from 31 Aug 2026. Source: developer.android.com/google/play/requirements/target-sdk,
checked 12 Nov 2026. R8 minification and resource shrinking are on for release.

## D-009 App name and package (proposed)
Display name "Toddler English", application id and package `app.toddlerenglish`. The application id cannot be
changed after the first Play upload, so the owner should confirm it before S8.

## D-010 Theme (proposed)
One calm light palette (tokens in `ui/theme/Tokens.kt`). The app does not follow system dark mode, so scenes
look the same for every child. Text contrast is checked in S7.

## D-011 Build, lint and test commands (proposed)
Toolchain: JDK 17, Gradle 8.13 wrapper, AGP 8.11.2, Kotlin 2.2.21, Compose BOM 2025.10.01.
Format and lint: ktlint through `org.jlleitschuh.gradle.ktlint` 13.1.0 (rules in `.editorconfig`, Android Studio
style with trailing commas allowed) plus Android lint. Tests: JUnit 4 unit tests on the JVM.

    ./gradlew assembleDebug testDebugUnitTest      # S0 "done when"
    ./gradlew ktlintCheck lintDebug                # style and Android lint
    ./gradlew ktlintFormat                         # auto-fix style
    python scripts/validate_content.py             # content checks
    ./gradlew bundleRelease                        # release AAB (needs keystore.properties, see RELEASE.md)

Every `assemble` and `bundle` task also runs `check<Variant>Permissions`, which fails if the merged manifest
contains INTERNET, ACCESS_NETWORK_STATE or AD_ID. CI (`.github/workflows/ci.yml`) runs content validation,
ktlintCheck, lintDebug, testDebugUnitTest and assembleDebug on every push.

## D-012 Content model (proposed)
Content lives in `assets/content/` as JSON: words, phrases, scenes (+ per-scene layouts), games, songs.
Word schema: id, text, scene, tier, audio, image, tags, translations (docs/CONTENT.md). Images are Android
drawables named `img_<id>` so art can be swapped by file name; audio is `assets/audio/<kind>/<id>.ogg`.
`scripts/validate_content.py` checks ids, files, tiers, references and the 2-places rule. Until S6 CI runs it
with `--lenient` (usage rule as a warning); from S6 it runs strict.

## D-013 Placeholder voice (proposed)
No TTS skill or tool was available in this environment, and espeak-ng/piper are not installed. The one generator
`scripts/gen_audio.py` uses the Windows built-in voice "Microsoft Zira Desktop" (System.Speech), then trims,
loudness-normalises (-19 dB RMS, peak 0.89) and writes mono Ogg Vorbis at 22.05 kHz. The licence for
redistributing Windows voice output in a published app is not confirmed. Before the Play release the owner must
either confirm the rights or replace the voice (a recorded human voice is best for toddlers; piper with a
CC-BY voice is the fallback). Swapping is one change in `gen_audio.py` plus `--force`.

## D-014 Art approach (proposed)
Word and scene art are VectorDrawables generated by `scripts/gen_art.py` from simple original shapes. Each file
can be replaced by hand-made art with the same name; the generator only overwrites files that carry its marker.
`python scripts/art_preview.py` writes `build/art-preview.html` for a visual check.

## D-015 Mascot (proposed)
The mascot is Pebble, an original round seed-bird with a leaf sprout (docs/MASCOT.md), drawn in Compose
Canvas so it animates without image assets.

## D-016 Word list and tiers (proposed)
100 words, 20 per scene: home, farm, food, bedtime, outdoors. Tier 1 = short concrete first words
(35 words), tier 2 = common next words (39), tier 3 = longer or more abstract words (26), for example
"butterfly", "quiet", "dream". Every scene has at least 6 tier-1 words so tier-1 games have enough choice.

## D-017 Parental gate (proposed)
Two steps: press and hold a circle for 3 seconds, then type the answer to an addition written in words
("sixteen plus nine") on a 0-9 keypad. Answers are always two digits. A wrong answer silently returns to step 1
with a new question. Children aged 1-5 cannot read the words. `ParentalGateTest` simulates 20,000 random toddler
sessions (taps, some long presses, random keys) and requires fewer than 1% to open the gate.

## D-018 Back button (proposed)
Back on the home screen is consumed (Pebble does a little nod), so a toddler cannot leave by accident. Back in
any other child screen returns home. Grown-ups leave via "Close the app" in the parent corner. Home and Recents
buttons cannot be blocked without screen pinning, which is left to parents (documented in the tester guide).

## D-019 Defaults (proposed)
Default word tier 1, play-time limit 10 minutes, sound on. All three are parent settings in DataStore.

## D-020 Stickers and progress (proposed)
Stickers are data (`content/stickers.json`): 15 for hearing 5, 10 and 15 different words in each scene, 8 for
playing each game once and ten times, plus one per song (added in S6). Stickers are only ever added. Empty spots
in the sticker book are soft dotted circles that invite play, never "locked" icons. Progress stores only counts
(words heard, rounds played, songs finished, minutes played) in a local DataStore file, excluded from cloud backup.

## D-021 A positive response to every tap (proposed)
Every child screen answers every tap: items speak and animate; empty space makes a sparkle burst and Pebble nods
(`TapSparkles`, scene hit-test fallback). Pebble has no sad or cross mood. `ChildRulesTest` fails the build if a
spoken phrase contains a negative word or child-screen code mentions wrong answers, game over, lives, countdowns
or streaks.

## D-022 Mini-games and tiers (proposed)
Four games from `games.json`, all reading words at or below the parent's tier:
- **Bubbles:** pictures float up in bubbles; every pop says the word. Tier 1/2/3 = 3/4/5 bubbles, 9/7.5/6 s rise.
- **Find it (match):** Pebble says "Can you find the ..."; 2/3/4 pictures by tier. Another picture is named and
  wiggles, then Pebble asks again. No failure sound or mark.
- **Feed Pebble:** tier 1 Pebble eats whatever is tapped; from tier 2 Pebble asks for one food by name; 2/3/4 foods.
- **Sing-along:** tier 1 shows the picture of the word being sung, tier 2 adds the current lyric line with the
  sung word highlighted, tier 3 adds the next line.
Every game runs endless gentle rounds (8 pops, 5 finds, 5 feeds, 1 song); a finished round only feeds stickers.

## D-023 Play-time limit (proposed)
`SessionTimer` counts only time on child screens while the app is resumed (each tick capped at 5 s, so a
backgrounded app adds nothing). At the limit the app shows the rest screen (Pebble sleeping, spoken "Time for a
little rest"), with no countdown before it. Only the parental gate leads out; opening the gate starts a fresh
session. Minutes played are added to progress for the parent corner.

## D-024 Songs (proposed)
Seven short original chants (Farm Friends, Yummy Food, Good Night, Look Outside, Where Is It?, Rain and Sun,
Animal Sounds). Each lyric token is spoken by the voice and placed on a beat over soft generated tones, so word
timings are exact and stored in `songs.json`. They sound like a rhythmic chant rather than singing; a recorded
singer can replace any `audio/songs/<id>.ogg` later, keeping or re-measuring the timings. Each song earns a sticker.

## D-025 Scene item halos (proposed)
Every scene item sits on a soft white halo (`Palette.SceneHalo`). It keeps green things visible on grass and
tan things on wooden floors, and makes it obvious that each item can be tapped.
